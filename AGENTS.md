# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Project

`pyokf` — a Python library and CLI for the [Open Knowledge Format (OKF)](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf), an open spec published by Google Cloud where knowledge is a directory of markdown files with YAML frontmatter. Developed and maintained by Gwenlake. Apache-2.0.

The spec is the contract: docstrings cite the sections they implement (`SPEC §4`, `§5.3`, `§9`, `§11`). When changing parsing, validation, or serialization behaviour, check the referenced section first.

## Commands

```bash
uv sync --dev                                   # create .venv and install dev deps
uv run pytest tests/ -q                         # full test suite (fast, no network)
uv run pytest tests/test_pyokf.py::test_bm25_query -q   # a single test
uv run ruff check pyokf tests                   # lint (E, F, I, UP, B; line-length 92)
uv run ruff check --fix pyokf tests
uv build                                        # wheel + sdist via the uv_build backend
uv run pyokf --help                             # run the CLI from the working tree
```

The dataviz palette validator used for the HTML graph lives in the `dataviz` skill
(`node scripts/validate_palette.js "<hex,…>" --mode light|dark --pairs all`); re-run it
if you change the colours in `graph.py`.

## Architecture

Strictly layered; imports only ever go downward:

```
trust.py     Stamp, Source, date parsing  — v0.2 signal primitives, no deps
concept.py   Concept: frontmatter <-> text, links, trust_tier, staleness
bundle.py    Bundle: dict-like collection, disk/archive I/O, validation, index/log
             + find_bundle_root / is_bundle_root (how the CLI locates a bundle)
             ├── graph.py    DOT / Mermaid / JSON / self-contained HTML view
             ├── search.py   Index: pure-Python BM25 over a Bundle
             ├── readers.py  file -> plain text (stdlib; PDF/docx lazily imported)
             ├── llm.py      ingest_text / ingest_dir / ask (uses readers + search)
             ├── mcp.py      stdio JSON-RPC MCP server over a Bundle + Index
             └── cli.py      argparse front-end over everything above
```

Load-modify-save is the only persistence model: `Bundle.load(root)` → mutate in memory → `bundle.save(root)`. `save()` rewrites every concept file plus a regenerated `index.md` per directory; there is no partial write path.

**The CLI is bundle-relative, like git** (since 0.5.0). No command takes the bundle as a positional argument: `_root(args)` uses `-C/--bundle` if given, else `find_bundle_root()` walks up from the cwd (a root is an `index.md` declaring `okf_version`, or a directory with `log.md`). Two consequences when editing `cli.py`: `-C` is defined on a shared `parents=[common]` parser — never call `set_defaults(bundle=…)`, which mutates that shared action and breaks `-C` placed before the subcommand — and every `cmd_*` gets its root from `_load(args)`, never from an argument. `_legacy_bundle_arg` turns the pre-0.5 form into a migration hint.

## Invariants worth knowing before editing

- **Concept ID = path relative to the bundle root, without `.md`** (`tables/orders.md` → `tables/orders`). Normalized by `bundle._norm_id`, which rejects `..`. Links resolve through `_resolve_link` (bundle-absolute `/…` or source-relative).
- **`index.md` and `log.md` are reserved** (`RESERVED_FILENAMES`): never loaded as concepts, rejected by `Bundle.add`, and fully regenerated by `save()` / `append_log`. The bundle-root `index.md` is the *only* index allowed frontmatter — it carries `okf_version` (SPEC §11).
- **Lossless round-trip.** Unknown frontmatter keys land in `Concept.extra` and are re-emitted verbatim; `frontmatter_dict()` fixes the key order (type → descriptive → v0.2 signals → extras). Any new frontmatter field must be popped in `from_text` *and* written in `frontmatter_dict`, or it silently migrates into `extra`.
- **Consumption is permissive (SPEC §9).** Only an empty/missing `type` is fatal. Broken links, unknown types, unknown statuses, stale dates, and dangling `[^footnotes]` are warnings — broken links may be not-yet-written knowledge and are kept as graph edges (rendered as ghost nodes). `Bundle.load(strict=False)` skips unparseable files rather than failing.
- **Trust tiers are derived, never stored**: `verified` stamps with a `human:` prefix ⇒ `human-reviewed`, other stamps ⇒ `machine-confirmed`, none ⇒ `unverified`. Absent `status` means `stable`.
- **v0.1 compatibility**: the legacy `timestamp` field is read into `generated.at` and re-serialized in v0.2 form. Keep that mapping in both `Concept.from_text` and `Bundle.create`.
- **The library never executes anything from a bundle.** OKF records computations; running them is a consumer concern (Attested Computation fields just round-trip via `extra`).

## LLM code

Every LLM entry point takes `complete(system, user) -> str`. `anthropic_complete` (stdlib `urllib`, `ANTHROPIC_API_KEY`, no SDK) is only the default — tests always inject a fake completer, so the suite never touches the network. Keep any new LLM feature behind that same callable.

Ingestion contract: generated concepts are stamped `generated: {by: pyokf/<model>}` and left **unverified**; ID collisions get a numeric suffix rather than overwriting; `ingest_dir` makes one call per file so a single bad file can't sink a run, and records the originating path in `sources`.

## The HTML graph view

`graph.to_html` returns one self-contained page (inline CSS/JS, no CDN, nothing fetched — a test asserts the only URL in the output is the SVG namespace). It ships a hand-written force layout rather than a charting library, keeping the zero-dependency rule.

**The page draws two edge kinds.** `_payload` emits `kind: "link"` (markdown links — the OKF graph, SPEC §5) and `kind: "tree"` (folder containment, with a `dir:`-prefixed node per path segment; the prefix exists because `papers.md` and `papers/` can coexist). Without the tree, a freshly ingested bundle renders as isolated dots, since its concepts have no cross-links yet.

**Test the page by running it, not by reading it.** `test_html_graph_boots_and_frames_itself` evaluates the page's JS against a stub DOM under `node` (skipped when `node` is absent). It exists because two separate defects shipped from review alone: a `const` referenced before its declaration killed the whole script at load (valid syntax, so `node --check` passed), and the view applied no transform until the layout settled, leaving nodes off-screen. The test also drags a node for 400 simulated frames to check the layout is still reacting late in the drag. If you touch the script, run that test rather than trusting a read-through. The colour encoding follows the project's dataviz rules: a node-link diagram is an *all-pairs* form, so only the **three** largest top-level directories get a categorical hue (validated for both light and dark surfaces) and the tail shares a neutral; every node keeps a visible label and the legend and table view exist so identity is never colour-alone. Changing those hues means re-running the validator for both modes.

## Dependencies

Runtime is **PyYAML only**. `pypdf` / `python-docx` are the optional `docs` extra and must stay lazily imported inside `readers.read_text`, degrading to a `ReaderError` with an install hint — a PDF must never crash a run, only be skipped. `uv sync --dev` does not install extras, so reading real PDFs from a clone needs `uv run --extra docs …`; a later plain `uv sync` prunes it back out. The MCP server, BM25 index, and Anthropic client are all stdlib on purpose — don't add a dependency to solve something small.

## Tests

Everything lives in `tests/test_pyokf.py`, grouped by banner comment (core spec, v0.2 signals, CLI, LLM, graph/stats/archives, search/MCP). Conventions: `tmp_path` for disk round-trips, `capsys` + `cli_main([...])` for CLI commands (assert on the exit code), `fake_complete` for ingestion, `_rpc(server, ...)` helpers for MCP. French fixtures are deliberate — they exercise accent-insensitive tokenization and the "answer in the input language" behaviour.
